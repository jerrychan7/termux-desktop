# 多语言与 CJK 显示

> 状态：阶段一已完成（修复与复测见下），阶段二未开始。本文随进展更新。

## 现在知道什么

已经确认的事实：

- 宿主 `$PREFIX/share/locale` 是空的，宿主 XFCE 当前没有可用的翻译文件。
- 宿主 x11-repo 提供 `otf-noto-sans-cjk`；容器里可用的中文字体包有 `fonts-wqy-microhei`、`fonts-wqy-zenhei`、`fonts-noto-cjk`。

还没有验证、因此不能当结论的事情（阶段一的验证结果见本页后半部分）：

- 宿主当前有没有能显示中文的字体（`fc-list :lang=zh`）。
- Termux 使用的 libc 是否接受 `zh_CN.UTF-8`；接受之后，Xlib 的窗口标题和剪贴板是否还会退化。
- 已安装的 XFCE 包是否带翻译文件。`dpkg -L` 列出已安装包的文件清单就能判断，不需要安装。
- 宿主和容器的 `.desktop` 文件里有没有 `Name[zh_CN]` 这类内联翻译。

先装字体或语言包会把“缺不缺”测成“装了就不缺”，出问题时也分不清是字体、locale 还是翻译数据。所以验证阶段不装任何东西。

## 阶段一：CJK 能正常显示

范围是文本内容、文件名、窗口标题、剪贴板、菜单名。宿主和容器各测一遍：两边的字体和 locale 互相独立，修法也不同。

| 编号 | 检查 | 做法 | 通过标准 |
|---|---|---|---|
| P1-1 | 字形覆盖 | 宿主检查 `/system/fonts`，用 Firefox 无头截图确认；容器里跑 `fc-list :lang=zh` | 至少匹配到一个字体；页面里没有方框和空白 |
| P1-2 | 文件名 | 在 `~` 和 `/sdcard` 各建一个中文名文件，用 Thunar 和终端查看，再复制粘贴 | 两处显示一致；粘贴回来还是原来的名字 |
| P1-3 | 窗口标题 | 宿主用 Firefox 和 Thunar 的窗口标题；容器里用 xterm 的标题参数 | 标题栏显示正确的中文 |
| P1-4 | 剪贴板 | 宿主 Firefox 与 Thunar 双向复制；容器里用带输入框的应用粘贴 | 往返内容一致，不丢字、不变问号 |
| P1-5 | 菜单名 | 容器里放一个带 `Name[zh_CN]` 的临时 `.desktop`，`desk app refresh` 之后检查生成的宿主菜单文件 | 生成的文件里保留了中文名；菜单实际显示哪种语言取决于会话语言，属于阶段二 |

P1-2 的文件和 P1-5 的 `.desktop` 都是临时测试产物，测完删除。

窗口标题由人看，不安装 `xprop`、`wmctrl` 之类的工具。

失败时的归因只有四类：字体覆盖（fontconfig 里没有中文字体）、locale（`zh_CN.UTF-8` 不被接受，或 Xlib 处理不了）、翻译数据（`.mo` 不存在）、我们自己的代码（例如菜单解析只读 `Name`，不读 `Name[zh_CN]`）。

## 阶段二：XFCE 界面能切换语言

范围是宿主 XFCE 的界面文字。容器里应用自己的界面语言由各容器的包负责，不在这一阶段。

真正要回答的是三件事：

1. 翻译数据在不在。宿主 `$PREFIX/share/locale` 为空，需要先查清是“没装”还是“Termux 打的包不带翻译”。`dpkg -L` 看已安装包的文件清单就能判断，不需要安装。
2. 如果数据不存在，能否从外部取得，版本能不能对上。这一步是评估成本和风险，不是开关。
3. 如果数据存在，切换是什么形态：安装时选择、写一个配置项，还是文档里让用户自己改环境变量。宿主没有登录管理器，切换要重启会话才生效，不存在热切换；切回英文也要同样能用。

界面语言多半只能靠 `LANGUAGE`、`LC_MESSAGES` 这类变量实现，`LC_CTYPE` 可能需要保持 `C.UTF-8`，否则标题和剪贴板会退化。这一点也要先测，不能直接写成结论。

阶段二和阶段一不对称：阶段一在现有环境里就能测完；阶段二大概率只能测到“数据不存在、也拿不到”，之后要么接受英文界面，要么立项去收集翻译文件。

## 验证顺序

1. 宿主：`fc-list :lang=zh` → 文件名 → 标题 → 剪贴板 →（可选）菜单测试项
2. 容器：`fc-list :lang=zh` → 文件名 → 剪贴板 →（可选）标题
3. 单进程对照：`LANG=zh_CN.UTF-8 locale charmap`，看返回什么；标题和剪贴板在 `zh_CN.UTF-8` 下的行为也只做单进程测试，不改会话脚本
4. 汇总成“通过/失败 + 证据 + 归因”的表，再谈修复

## 阶段一的验证结果（2026-11-11）

环境：设备上通过 `install.sh` 安装的 desk 0.0.2，宿主 XFCE 会话，容器 `ubuntu` 和 `ubuntu-desktop-test`（Ubuntu 26.04）。临时测试文件和菜单测试项已删除。

宿主：

- 中文字形来自 Android 的 `/system/fonts`（`NotoSansCJK-Regular.ttc`、`NotoSerifCJK-Regular.ttc`、`SysFont-Hans/Hant`），fontconfig 的 `fonts.conf` 包含这个目录。Firefox、Thunar、面板任务栏都能正常显示简体、繁体和标点；Firefox 无头截图同样正常。
- 宿主的 `fc-list`、`fc-match` 不可用（`fontconfig` 包不带命令行工具），字体覆盖改用无头截图和字体文件确认。
- 只有 `C.UTF-8` 和 `C` 可用；`zh_CN.UTF-8` 的 `setlocale` 直接失败，`en_US.UTF-8` 被映射回 `C.UTF-8`。会话固定 `C.UTF-8` 是有依据的。
- 已安装的 XFCE 包声明的 `.mo` 数量为 0，宿主没有翻译文件。
- Thunar 的文件名、标题栏、地址栏都正常；Firefox 与 Thunar 之间双向复制中文正常。

容器：

- 两个容器 `fc-list :lang=zh` 都是 0，没有中文字体；`locale -a` 只有 `C`、`C.utf8`、`POSIX`；`/usr/share/locale` 里有 `zh_CN`、`zh_TW` 和 2 个中文 `.mo`，但 locale 没生成，用不了。
- 通过 `desk app launch` 启动的 xterm，标题和正文都是乱码（字节按非 UTF-8 解释）。`/proc/<pid>/environ` 里只有 `DISPLAY`，没有 `LANG`/`LC_ALL`，容器里是 C locale。
- 用 `env LANG=C.UTF-8 LC_ALL=C.UTF-8` 强制启动后，xterm 标题栏恢复正常，正文变成方块，说明标题和内容坏在不同层面：标题缺 locale，内容缺字体。
- 容器里创建中文文件名成功，但缺字体，无法用 GUI 判断显示；C locale 下 `ls` 显示八进制转义，属于预期。

菜单：

- 给容器加一个带 `Name[zh_CN]=测试菜单项` 的临时 `.desktop`，`desk app refresh` 生成的条目只剩 `Name=CJK Menu Test (ubuntu-desktop-test)`，中文名被丢弃。`parse_desktop_entry` 只读 `Name`，不读 `Name[zh_CN]`。

## 补充验证：把宿主字体绑进容器（2026-11-11）

在决定用绑定之前，先用临时命令验证了这条路的可行性和边界，没有改仓库代码：

- `proot-distro sh ubuntu --isolated --shared-tmp --bind /system/fonts:/usr/share/fonts/truetype/android` 可以直接工作，目标路径不需要预先存在：即使绑到 `/nonexistent/a/b`，容器里也能访问，退出后这个目录跟着消失，不会在容器里留下挂载点。
- 容器里 `fc-list :lang=zh` 从 0 变成 60，Noto Sans/Serif CJK 的 SC、TC、HK、JP、KR 都在，字体总数从 8 变成 554。
- 只读由文件系统保证：容器里 `touch /usr/share/fonts/truetype/android/probe` 返回 `Read-only file system`，不需要额外的只读参数。
- fontconfig 缓存写在容器自己的 `/var/cache/fontconfig`，约 1 MB，没有碰宿主。
- 偏差：`fc-match :lang=zh-cn` 默认选中 `Noto Sans CJK JP`，不是 SC，汉字写法会带日文字形变体。宿主侧后来由 `desk setup` 写入偏好解决（见“补充：宿主字体偏好”）；容器内的 fontconfig 是另一套，这条仍成立。
- xterm 自身不做逐字回退：绑定后 `xterm -fa 'Noto Sans CJK SC'` 能正常显示中文，默认字体仍是方块；GTK 应用（Pango）会按字符回退到 Noto，不受这个限制。

结论：采用把 `/system/fonts` 绑进容器的做法，见 [D-032](decisions.md)。

与本次验证无关但记录在案：

- 宿主 `xfce4-terminal` 启动失败：缺 `libicuuc.so.78`，宿主包本身有问题。
- 陈旧 `$PREFIX/tmp/.X0-lock` 里的 PID 被别的应用复用，`desk start` 读 `/proc/<pid>` 得到 EACCES 后退出。已单独提交 `12d9d1f` 修复。

结论：

- 宿主 P1-1、P1-2、P1-3、P1-4 通过；P1-5 的数据层需要修复：解析器要保留 `Name[zh_CN]` 这类内联翻译，菜单显示中文则取决于会话语言，属于阶段二。
- 容器 P1-1 失败（没有中文字体），P1-3 在不补 locale 的情况下失败；P1-2 因为缺字体无法判断显示；P1-4 没测（容器里的 xterm 没有可用的粘贴操作），宿主的 X11 剪贴板路径已验证通过。
- 修复方向见 [D-032](decisions.md)：`desk app launch` 在宿主存在 `/system/fonts` 时把它绑进容器的字体目录，并传入 `LANG`/`LC_ALL=C.UTF-8`；菜单生成保留内联翻译名。修复后按上表复测。

## 修复与复测（2026-11-11）

按 [D-032](decisions.md) 实现，分两个提交：

- `e54b99b`：`desk app launch` 在宿主存在 `/system/fonts` 时绑定到容器的 `/usr/share/fonts/truetype/android`，并传入 `LANG`/`LC_ALL=C.UTF-8`。
- `9ac0cc6`：生成的菜单条目保留 `Name[locale]` 内联翻译。

复测（用仓库里的新代码在设备上直接跑，没有覆盖已经安装的 0.0.2）：

- 新启动路径的环境和挂在容器里都能看到：`LANG=C.UTF-8`、`LC_ALL=C.UTF-8`，`/usr/share/fonts/truetype/android` 有 224 个文件。
- 容器里用 Pango（和 GTK 同一套文本栈）把“中文内容测试：绑定字体”渲染成图片，中文正常。
- 容器里 `ls` 输出的三个中文文件名再用 Pango 渲染，`中文文件名.txt`、`中文文件夹`、`包含空格 和,标点.txt` 都正常。
- 容器里 `xterm -fa 'Noto Sans CJK SC'` 显示正常；不带字体参数的 xterm 仍然是方块，这是 xterm 自身不做逐字回退导致的，不是绑定或 locale 的问题。
- 剪贴板用两种 X11 客户端交叉验证：容器里 `xsel` 设置“容器复制的中文：剪贴板测试”，宿主侧一个临时的 `ctypes` Xlib 客户端能读回同样的内容；反过来，宿主侧那个客户端提供“宿主侧设置的中文：剪贴板测试”，容器里的 `xsel` 也能读回。临时脚本用完已删除，没有在设备上安装任何东西。
- 顺带发现 `termux-clipboard-get` / `termux-clipboard-set` 和 X11 剪贴板没有同步：`get` 返回空，`set` 之后容器读到的还是旧内容。本次没有追查，剪贴板验证改用 Xlib 客户端完成。
- 临时 HOME 目录里跑 `desk app refresh`，生成的条目包含 `Name[zh_CN]=测试菜单项`；测试项和临时 HOME 已删除。

- xterm 这类自己不做逐字回退的终端需要指定字体或改配置才能显示中文；GTK 应用不受影响。
- 宿主 fontconfig 默认把中文回退到 Noto CJK 的 KR/JP 面；`desk setup` 现在会写入 `$PREFIX/etc/fonts/conf.d/63-cjk-prefer-sc.conf` 修正（拉丁文本仍用 DejaVu），已经运行的应用要重启才生效；容器里的 fontconfig 是另一套，仍按原来的顺序选择。
- 绕过 `desk app launch`、直接 `proot-distro login` 启动的应用拿不到字体绑定和 locale。
- 设备上安装的 desk 还是 0.0.2，本次修复要等下一次安装或发布才生效。

## 补充：宿主字体偏好（2026-11-12）

- 实现：`desk setup` 探测设备上实际存在的简中字体家族（Noto 优先，其次 `OPPO Sans 4.0 SC` 等厂商面），生成 `$PREFIX/etc/fonts/conf.d/63-cjk-prefer-sc.conf`；编号 63 放在 `60-latin` 之后、`65-nonlatin` 之前。
- 实测（宿主，新进程）：`sans-serif` → DejaVu Sans；`sans-serif:charset=4E2D` → Noto Sans CJK SC；`serif:lang=zh-cn` → Noto Serif CJK SC；`monospace` → DejaVu Sans Mono；`monospace:charset=4E2D` → Noto Sans CJK SC。
- 设备上本次探测到 `Noto Sans CJK SC`、`Noto Serif CJK SC`；`monospace` 没有 Mono CJK 面，回退到 `Noto Sans CJK SC`。
- 撤销：`desk font remove` 删除带生成标记的文件；`desk uninstall --purge` 也会回收。已经运行的应用要重启才回到原来的回退。
- 容器里的 fontconfig 是另一套，这个文件不影响容器。

## 工具约束

- 不安装 `xprop`、`wmctrl`；窗口标题由人看。
- 允许给单个进程改环境变量做对照，不改会话脚本、不改模板。
- 允许试一次 Firefox 的 `--headless --screenshot` 截中文页面，取回图片看字形；不能正常截就放弃，不为量具修工具。
- VNC 延后到阶段二再考虑，而且只作为开发期查看画面的手段，不作为产品功能；路线图里“明确不做 VNC”指的是产品不提供 VNC 接入。如果引入，要镜像现有的 `:0` 会话，不另开一个会话，并在安装前后对比 `dpkg` 的差异，确认没有顺带装进字体或语言包。
- 修复按失败的那一层做最小改动，改完用同一条命令复测。

## 不做什么

- 验证前不安装字体、语言包、测量工具。
- 不把“可能缺什么”当成“缺什么”。
- 不把阶段二描述成改一个环境变量就能完成。
