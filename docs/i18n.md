# 多语言与 CJK 显示

> 状态：验收范围和验证顺序已定，尚未开始实际验证。本文随验证结果更新。

## 现在知道什么

已经确认的事实：

- 宿主 `$PREFIX/share/locale` 是空的，宿主 XFCE 当前没有可用的翻译文件。
- 宿主 x11-repo 提供 `otf-noto-sans-cjk`；容器里可用的中文字体包有 `fonts-wqy-microhei`、`fonts-wqy-zenhei`、`fonts-noto-cjk`。

还没有验证、因此不能当结论的事情：

- 宿主当前有没有能显示中文的字体（`fc-list :lang=zh`）。
- Termux 使用的 libc 是否接受 `zh_CN.UTF-8`；接受之后，Xlib 的窗口标题和剪贴板是否还会退化。
- 已安装的 XFCE 包是否带翻译文件。`dpkg -L` 列出已安装包的文件清单就能判断，不需要安装。
- 宿主和容器的 `.desktop` 文件里有没有 `Name[zh_CN]` 这类内联翻译。

先装字体或语言包会把“缺不缺”测成“装了就不缺”，出问题时也分不清是字体、locale 还是翻译数据。所以验证阶段不装任何东西。

## 阶段一：CJK 能正常显示

范围是文本内容、文件名、窗口标题、剪贴板、菜单名。宿主和容器各测一遍：两边的字体和 locale 互相独立，修法也不同。

| 编号 | 检查 | 做法 | 通过标准 |
|---|---|---|---|
| P1-1 | 字形覆盖 | 宿主和容器各跑 `fc-list :lang=zh`；Firefox 打开一个中文页面 | 至少匹配到一个字体；页面里没有方框和空白 |
| P1-2 | 文件名 | 在 `~` 和 `/sdcard` 各建一个中文名文件，用 Thunar 和终端查看，再复制粘贴 | 两处显示一致；粘贴回来还是原来的名字 |
| P1-3 | 窗口标题 | 宿主运行 `xfce4-terminal --title=中文标题`；容器里用 xterm 的标题参数做对照 | 标题栏显示正确的中文 |
| P1-4 | 剪贴板 | Firefox 和终端之间双向复制中文 | 往返内容一致，不丢字、不变问号 |
| P1-5 | 菜单名 | 容器里放一个带 `Name[zh_CN]` 的临时 `.desktop`，`desk app refresh` 之后检查生成的宿主菜单文件，再打开菜单看显示 | 生成的文件里保留了中文名，菜单显示正常 |

P1-2 的文件和 P1-5 的 `.desktop` 都是临时测试产物，测完删除。

窗口标题由人看，不安装 `xprop`、`wmctrl` 之类的工具。

失败时的归因只有四类：字体覆盖（fontconfig 里没有中文字体）、locale（`zh_CN.UTF-8` 不被接受，或 Xlib 处理不了）、翻译数据（`.mo` 不存在）、我们自己的代码（例如菜单解析只读 `Name`，不读 `Name[zh_CN]`）。

## 阶段二：XFCE 界面能切换语言

范围是宿主 XFCE 的界面文字。容器里应用自己的界面语言由各容器的包负责，不在这一阶段。

真正要回答的是三件事：

1. 翻译数据在不在。宿主 `$PREFIX/share/locale` 为空，需要先查清是“没装”还是“Termux 打的包不带翻译”。`dpkg -L` 看已安装包的文件清单就能判断，不需要安装。
2. 如果数据不存在，能否从外部取得，版本能不能对上。这一步是评估成本和风险，不是开关。
3. 如果数据存在，切换是什么形态：安装时选择、写一个配置项，还是文档里让用户自己改环境变量。宿主没有登录管理器，切换要重启会话才生效，不存在热切换；切回英文也要同样能用。

界面语言多半只能靠 `LANGUAGE`、`LC_MESSAGES` 这类变量实现，`LC_CTYPE` 可能需要保持 `C.UTF-8`，否则标题和剪贴板会退化。这一点也要先测，不能直接写成结论。

阶段二和阶段一不对称：阶段一在现有环境里就能测完；阶段二大概率只能测到“数据不存在、也拿不到”，之后要么接受英文界面，要么立项去收集翻译文件。

## 验证顺序

1. 宿主：`fc-list :lang=zh` → 文件名 → 标题 → 剪贴板 →（可选）菜单测试项
2. 容器：`fc-list :lang=zh` → 文件名 → 剪贴板 →（可选）标题
3. 单进程对照：`LANG=zh_CN.UTF-8 locale charmap`，看返回什么；标题和剪贴板在 `zh_CN.UTF-8` 下的行为也只做单进程测试，不改会话脚本
4. 汇总成“通过/失败 + 证据 + 归因”的表，再谈修复

## 工具约束

- 不安装 `xprop`、`wmctrl`；窗口标题由人看。
- 允许给单个进程改环境变量做对照，不改会话脚本、不改模板。
- 允许试一次 Firefox 的 `--headless --screenshot` 截中文页面，取回图片看字形；不能正常截就放弃，不为量具修工具。
- VNC 延后到阶段二再考虑，而且只作为开发期查看画面的手段，不作为产品功能；路线图里“明确不做 VNC”指的是产品不提供 VNC 接入。如果引入，要镜像现有的 `:0` 会话，不另开一个会话，并在安装前后对比 `dpkg` 的差异，确认没有顺带装进字体或语言包。
- 修复按失败的那一层做最小改动，改完用同一条命令复测。

## 不做什么

- 验证前不安装字体、语言包、测量工具。
- 不把“可能缺什么”当成“缺什么”。
- 不把阶段二描述成改一个环境变量就能完成。
